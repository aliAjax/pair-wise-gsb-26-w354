# hxwl-12 心理咨询个案记录 · 联合会谈记录台

两位咨询师同场接待时的联合记录工作台：私密观察 → 点名分享 → 共同草稿 → 双方确认 → 正式纪要 → 对外导出过滤。

## 技术栈

React 19 + Vite + TypeScript + CSS（无后端，数据持久化在浏览器 localStorage）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5112

## 工作流与规则

1. **身份切换**：右上角在主接 / 协同两位咨询师之间切换（同机双角色演示），身份偏好本地记忆。
2. **① 私密观察区**：每位咨询师只能看到自己写的观察，对方不可见。
   - 每条可标记「一般内容 / 涉及来访者亲属 / 涉及未经同意第三人」；后两者需勾选「已取得书面同意」才能放行。
   - 敏感且未同意的段落**锁定在私密区**，分享按钮禁用并显示原因。
3. **② 共同草稿**：只有作者本人点击「点名分享」，内容才会进入共同草稿。
   - 每段由两位咨询师**分别勾选确认**，任何人不能替对方确认。
   - 草稿文字被修改后，双方确认状态清零，必须重新确认。
   - 双方确认前，原作者可撤回到私密区。
   - **所有活动草稿全部双方确认**后，才能生成正式纪要。
4. **③ 正式会谈纪要**：
   - 生成后段落为快照；修订会创建**新版本**，完整保留每一版旧文本。
   - 每次修订必须填写**修改原因**，并记录操作人和精确时间；版本历史可逐条点开只读回看。
   - 纪要生成之后新增并双方确认的草稿，可在修订时并入新版本。
5. **导出正式摘要**：按最新版逐条判定——
   - 一般内容、或已授权的敏感内容：纳入；
   - 涉及亲属/未经同意第三人且未授权：**过滤且不显示正文**，逐条列出过滤原因；
   - 弹窗预览并可下载 `.txt`，文末附「共 N 条，纳入 X 条，过滤 Y 条」统计。
6. **重新打开**：全部数据（含待确认段落、逐段确认状态、版本历史、当前身份）存于 localStorage，刷新或重开页面后待确认段落仍在，顶部横幅提示未完成确认数。

## 代码结构

- `src/types.ts`：观察 / 草稿 / 纪要版本等领域模型
- `src/rules.ts`：保密门禁、确认状态、导出判定等纯规则
- `src/seed.ts`：覆盖「待确认 / 已确认 / 敏感锁定」三种情形的示例数据
- `src/store.ts`：`useSessionStore` 状态机与 localStorage 持久化
- `src/exporter.ts`：逐条过滤、原因说明与 txt 导出
- `src/App.tsx`：三栏工作台界面
